COMMON PROBLEMS

企业发行通常需要解决三类问题。

发行基础设施建设成本高

发行不仅包含提交表单，还涉及 Catalog、审核、渠道、状态、数据和收益。现有发行底座可减少重复建设。

业务规模增长后人工流程效率下降

客户、内容和发行量持续增长后，需要将流程、状态和责任沉淀到系统中。

已有系统需要保留

在线平台、API、DDEX、XML、SFTP 和 Excel 可按现有系统成熟度组合，减少整体重构。

HOW TO CHOOSE

四个标准决定接入方式。

客户入口

是否需要独立客户门户

需要下游客户直接使用时优先品牌发行平台；仅内部使用时可优先 API。

现有产品

是否已有成熟前端和账号体系

已有完整产品时优先 API；缺少完整发行产品时优先品牌发行平台。

数据规模

是否存在大规模历史 Catalog

大量既有内容需要优先设计迁移、批量导入和字段映射。

技术成熟度

是否已有专业发行数据流

标准业务可使用在线平台；成熟供应链可使用 API / DDEX / XML / SFTP。

发行流程

典型流程包括内容建立、资料校验、发行提交、渠道状态读取和后续报表获取。

// 接口结构示意，非正式生产 API
1. Create / sync artist, album and track
2. Validate release metadata
3. Configure target DSPs and schedule
4. Submit distribution
5. Receive status by query or webhook
6. Read reports / revenue after release

先校验，再提交

发行链路包含渠道规则和必要元数据。明确的校验步骤可减少提交后的资料返工。

Webhook

发行状态、交付结果等异步事件可通过 Webhook 回传，减少持续轮询。

// 事件结构示意
{
  "event": "distribution.status.updated",
  "resource_id": "release_xxx",
  "status": "delivered",
  "channel": "example_dsp",
  "occurred_at": "..."
}

正式事件名称和字段以生产文档为准。

错误与日志

登录后的开发者中心计划提供 API 调用日志和 Webhook 日志，用于定位参数校验、权限、渠道处理和系统异常。

类型必要信息处理方式
参数校验字段、原因、建议修复项修改请求后重试
鉴权 / 权限凭证、模块权限、环境检查 Credential / Entitlement
渠道处理目标 DSP、交付阶段、返回信息修正资料或等待渠道处理
系统异常Request ID、时间、状态携带 Request ID 联系技术支持

用量与额度

企业登录后可查看 API 调用量、发行使用量、套餐额度与超额情况。发行计费核心 Meter 为“歌曲 × 实际目标渠道”。
